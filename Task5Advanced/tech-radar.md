# Расширенный технический радар

## 1. Архитектурные паттерны

| Паттерн / подход | Статус | Комментарий |
|---|---|---|
|Event-Driven Architecture (EDA)| Adopt | Целевая интеграция через шину событий (Kafka); домены публикуют события, витрина и процессы подписываются. |
|Data Mesh| Trial -> Adopt | Домены владеют данными и Data Products; витрина строится из продуктов доменов. Пилот в 1–2 доменах, далее масштабирование. |
|Self-service BI| Adopt | Портала самообслуживания для отчётов по срезам в пределах уровня доступа. |
|Schema Registry + контракты событий| Adopt | Версионирование схем событий, обратная совместимость, снижение рисков при изменении контрактов. |
|Anti-Corruption Layer (ACL)| Adopt | Слой при миграции: адаптация легаси (DWH, Camel) к целевой модели событий и форматам витрины. |
|Централизованный DWH как единственный источник истины| Hold | Поэтапный вывод; остаётся только на время миграции. |
|Синхронная интеграция через ESB на критическом пути| Hold | Поэтапный вывод; остаётся только на время миграции. |

## 2. Данные и аналитика

| Технология / направление | Статус | Комментарий |
|---|---|---|
|Apache Kafka| Adopt | Единая шина для событий доменов; топики по контекстам, DLQ, потоковая доставка в витрину. |
|Data Catalog| Adopt | Каталог данных, права доступа, обнаружение Data Products для Self-service BI. |
|SQL Server 2008 (текущий DWH)| Hold | Поэтапный вывод после переноса потоков на события и витрину. |
|PowerBuilder (клиентский интерфейс)| Hold | Замена на современный стек в рамках доменных приложений. |

## 3. Интеграция и разработка

| Технология | Статус | Комментарий |
|---|---|---|
|REST| Adopt | Внутри доменов и для внешних партнёров |
|Apache Camel| Hold| Только на время миграции; новые потоки — через Kafka. |
|Golang, Java, Python | Adopt | Текущий стек финтиха + Python для ИИ сервисов; публикация событий в Kafka. |
|Infrastructure as Code (Terraform)| Adopt | Унифицированные среды (dev/stage/prod), облачная инфраструктура. |
|CI/CD| Adopt | Автоматизация развёртывания инфраструктуры и сервисов. |

## 4. Инфраструктура и облако

| Технология / практика | Статус | Комментарий |
|---|---|---|
|Облачная инфраструктура Yandex Cloud| Adopt | Основная часть ландшафта в облаке; отдельные среды по доменам. |
|Terraform (S3)| Adopt | Безопасное хранение состояния, совместная работа команд. |
|Отказоустойчивость и геораспределение| Adopt | Для критичных систем. |
|Секреты и управление доступом (IAM)| Adopt | Соответствие 152-ФЗ и отраслевым требованиям для мед- и финданных. |
|On-premise как основной хостинг| Hold | Миграция в облако в приоритете. |
